DEVELOPER GUIDE

How to deploy.

1. Connect a repository

Select Add repository, enter its HTTPS or ssh:// URL and branch, and choose authentication. For generated SSH keys, add the displayed public key as a read-only deploy key and configure verified host keys in the Git Deploy runtime before cloning.

2. Configure and deploy

After cloning, select .env on the repository card if the project needs environment variables, then select Deploy. Git Deploy pulls the branch and runs Docker Compose from its own clone. A successful first deployment enables polling; use Pause to stop checks. Inspect Activity after errors.

After deployment, Redeploy forces Compose to recreate services. View page uses the repository .env DOMAIN, or lets you choose a published TCP port using HTTP. Ensure the chosen service is a web page.

3. Existing deployments

Git Deploy does not automatically attach to existing containers. Check the Compose project name, environment files, ports, and persistent paths before deploying from the new clone; otherwise a second project or conflicting services may be created.

4. Removing a repository

Removal can optionally run Compose down and remove locally built images. This can affect any deployment sharing the Compose project name or image. Volumes are not removed. Back up data before proceeding.

Security and operations

Manual deploys, repository deletion, and container stop, kill, restart or pause require a fresh authenticator code. Codes cannot be reused, even after sign-in; wait for the next code. Automatic watcher deployments do not prompt.

This is an administrator-only tool with Docker host access. Protect the token, data directory, credentials and logs; use HTTPS through a secure proxy or an SSH tunnel. Host metrics require a read-only mount of the local Docker host's proc filesystem.
